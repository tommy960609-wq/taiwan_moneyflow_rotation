# 操作手冊（給投資決策者，非工程師）

**適用版本**：v1.0.0-software-ready-candidate
**最後更新**：2026-07-22

本手冊假設你**不寫程式**，只需要每天照步驟操作，看得懂報表在講什麼，遇到錯誤知道怎麼查。

---

## 1. 每天怎麼跑

### 1.1 一鍵執行（建議日常使用）

在檔案總管雙擊，或用 PowerShell/命令提示字元執行：

```
C:\Workspace_CN\taiwan_moneyflow_rotation\scripts\daily_run.bat
```

它會自動：
1. 先檢查最近 5 個日曆日的工作日是否有成功紀錄。
2. 官方資料已發布的缺口，依日期由舊到新自動補跑；尚未發布的日期只記錄等待，不會拿空資料硬跑。
3. 產生已就緒日期的 Excel 報表，並記錄訊號到歷史檔案（供之後統計用）。

**跑完怎麼知道結果？** 視窗最後一行會顯示：

| 顯示文字 | 意思 |
|---|---|
| `SUCCESS - 報表已產生` | 今天的報表可以打開看了 |
| `FETCH FAILED` | 網路或資料源掛了，**沒有**動到之前任何一天的舊資料 |
| `PIPELINE BLOCKED` | 資料品質不合格（見第 4 節），系統自動不出報表，避免你看到不可信的數字 |
| `UNEXPECTED EXCEPTION` | 系統本身出了非預期錯誤，需要工程師介入 |

若今天官方資料還沒公布，批次紀錄會顯示 `DEFERRED_NOT_READY`，這是正常等待，不是錯誤；
詳情看 `outputs\logs\orchestrator_batch_summary_<日期>.json`。

### 1.2 報表在哪裡

```
outputs\daily\MoneyFlow_Rotation_<日期>.xlsx
```

例如今天是 2026-07-18，檔名就是 `MoneyFlow_Rotation_2026-07-18.xlsx`。

### 1.3 想指定日期重跑（例如補跑昨天）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\daily_run.ps1 -Date 2026-07-17 -PrevDate 2026-07-16
```

若是補跑前一天，直接重新執行同一個 `daily_run.bat` 即可；TPEx 最新日端點若已滾到今天，程式會改用官方指定日期歷史行情補正，驗證日期後寫入資料，再產出前一天 Excel。若官方就緒探針尚未公布今天資料，會顯示 `DEFERRED_NOT_READY`，稍後再重跑即可。

## 2. 報表四張表怎麼讀

打開 Excel 後有 4 張工作表：

### 2.1 Dashboard（總覽）
- **資料品質分數（DQ Score）**：0-100 分，代表今天抓到的資料完不完整、乾不乾淨。95 分以上正常，85-94 有警告但仍可用，70 分以下系統會直接拒絕產出正式報表（見第 4 節）。
- **產業對應覆蓋率**：股票有沒有被歸類到正確產業族群的比例。
- **前十大族群**：今天資金/動能排名前十的產業族群。

### 2.2 新起漲族群
今天被系統標記為「剛開始有資金流入/動能出現」的產業族群，含分級（A/B/C）與判定理由。

### 2.3 續漲族群
系統判斷「已經在漲、可能持續」的族群。**本系統目前這張表在多數情況下是空的**——因為兩條判定規則（次龍頭接棒、高檔爆量不漲）還沒有資料來源可以評估,詳見「已知限制」。

### 2.4 個股優先排序
每個族群裡，系統認為值得優先關注的個股清單。

### ⚠️ 最重要的一句話：**訊號等級=未校準研究參考，不是買賣指令**

報表上的 A/B/C 分級、分數，全部是**尚未經過歷史驗證的研究讀數**。目前的回測結果（`docs/backtest_methodology.md`、`docs/Milestone_5c_Acceptance_Report.md`）顯示：這套訊號在過去 60 個交易日的樣本中，**沒有證據顯示比「單純買昨天最強族群」表現更好**，甚至略差。換句話說：**目前不能拿這張報表直接下單**，只能當作研究參考。

## 3. 常見錯誤對照表

| 訊息 | 代表什麼 | 你該做什麼 |
|---|---|---|
| `FETCH_FAILED` | 抓資料時網路失敗或官方 API 沒回應 | 通常晚一點重跑會自己好；如果連續好幾天都這樣，通知工程師檢查官方網站是否改版 |
| `BLOCKED_LOW_DQ` | 資料品質分數 <70 分（黑燈） | 系統**故意**不產生正式報表，避免用髒資料誤導。等下一個交易日資料正常後會恢復。查看 `outputs\logs\audit_<日期>.json` 看是哪裡出問題 |
| `BLOCKED_MISSING_MARKET` | 上市或上櫃其中一個市場的資料完全抓不到 | 通常是官方網站當天維護或改版；等隔天 |
| `BLOCKED_NO_MAPPING` | 找不到股票產業對照表檔案 | 這是系統設定問題，通知工程師 |
| `UNEXPECTED EXCEPTION` | 系統本身的程式錯誤，不是資料問題 | 通知工程師，附上 `outputs\logs\run_<日期>.log` |

## 4. 資料品質黑燈是怎麼一回事

系統每天執行前會替當天資料打分數（0-100），依分數決定要不要出報表：

| 分數 | 狀態 | 系統怎麼做 |
|---|---|---|
| 95-100 | 正常 | 正常出報表 |
| 85-94 | 警告 | 出報表，但 Dashboard 會顯示警告字樣 |
| 70-84 | 降級 | 出報表，但不產生高信心度訊號 |
| 70 以下 | **黑燈** | **完全不出正式報表**，只留一份錯誤紀錄（`outputs\logs\audit_<日期>.json`） |

這是刻意設計的保護機制：**寧可今天沒有報表，也不要給你一份看起來正常、實際上資料有問題的報表。**

## 5. 資料補齊進度怎麼查

系統仍在背景持續下載歷史資料（FinMind 資料源），因為官方 API 不提供歷史回補。想知道補到哪了：

```powershell
# 看目前已下載幾檔股票的歷史行情
(Get-ChildItem "data\raw\ohlcv\finmind_*.json").Count
# 除以 1963（全市場股票數）大約就是覆蓋率
```

或直接看背景程式的即時 log：
```
outputs\logs\finmind_drip.log        # 正常進度
outputs\logs\finmind_drip_err.log    # 錯誤訊息（若有）
```

## 6. FinMind 資料源的額度特性（工程師/進階使用者參考）

- FinMind 免費額度大約允許**每小時 570 次左右**的請求就會被限速（HTTP 402），實測是「短時間內爆發性」限速（約 30-90 秒內就會觸發下一輪冷卻），不是乾淨的整點重置。
- 系統的補抓腳本（`scripts\fetch_history_finmind.py --sleep-between 50`）刻意放慢速度（每次請求間隔 50 秒），用意是不要一次撞到限速上限，讓背景補抓可以連續跑好幾個小時不中斷。
- 這是長期任務，**不需要等它跑完**——它會自己在背景持續進行，不影響每天的 `daily_run` 正常運作（兩者互不干擾，各自讀寫不同的資料）。

## 7. Windows 工作排程器設定步驟（文件說明，本次交付**不會**幫你實際建立排程）

如果你希望系統每個交易日自動在特定時間執行，可依下列步驟自行建立（或請工程師協助）：

1. 開啟「工作排程器」（Task Scheduler）。
2. 「建立基本工作」→ 命名例如「台股資金輪動每日報表」。
3. 觸發程序選「每天」，建議同一個工作日建立三個觸發時間：18:30、20:00、22:00。每次都執行同一個 `daily_run.bat`，晚到的官方資料會自動補回；本次只提供文件建議，不會替你建立或修改工作排程器項目。
4. 執行動作選「啟動程式」：
   - 程式：`C:\Workspace_CN\taiwan_moneyflow_rotation\scripts\daily_run.bat`
   - 開始位置：`C:\Workspace_CN\taiwan_moneyflow_rotation`
5. 進階設定建議勾選：「不論使用者是否登入均執行」「即使電源不足也要喚醒」。
6. 設定完成後，建議先手動按「執行」測試一次，確認 Excel 報表有正常產生再放著自動跑。
7. 週末/國定假日：TWSE/TPEx 當天沒有交易，系統會在確認官方日期已經越過該日且已有空回應證據後標記 `HOLIDAY_SKIP`，不會無限重試；建議排程只設平日（週一至週五）以減少無意義的觸發。

## 8. 一句話重點回顧

- 每天執行：雙擊 `scripts\daily_run.bat`。
- 報表看不懂術語沒關係，先看 Dashboard 的 DQ 分數跟前十大族群。
- **報表上的訊號分級是研究參考，不是買賣建議。**
- 黑燈（不出報表）是保護機制，不是系統壞了。
- 有問題查 `outputs\logs\`，或把 log 傳給工程師。
