## 1. 一頁問題陳述(讀這段就懂為什麼要改)

回測反覆顯示:校準機制、資料補齊都做了,但**回測數字一動也不動**,連小數點都一樣。根因不是資料、不是門檻校準,而是**訊號偵測器太鬆,每個族群每天都被打上訊號,從來不會是「無訊號」**。

具體機制(已對碼定位):`src/signal_detector.py::_grade_new_gainer`(第 388-402 行)的 C 級判定是:

```python
if passed:   # 只要 10 條件裡「任何一條」通過就給 C 級
    return GRADE_C, ...
```

而 rule 7(龍頭股占比 ≤70%)、rule 8(過熱風險 <90)這類條件在**絕大多數正常交易日必然通過**——所以幾乎每個族群每天都至少拿到一個 C 級訊號,`GRADE_NO_SIGNAL` 幾乎永不出現。

**下游後果**:回測的事件抽取規則是「同族群訊號只算第一次出現為獨立事件」。當某族群 62 天天天有訊號、從不間斷,規則只在第一天(2026-04-20 cold-start 日,當時還沒有歷史可校準)算一次事件。結果 53 個事件裡 46 個全部塌縮在第一天,校準的效果永遠測不到。

**這批工作的目標**:讓偵測器學會在多數平凡日子正確輸出「無訊號」,只在真正符合「族群性起漲」條件時才發訊號。這樣事件才會分散到各交易日,校準效果才有機會被回測量到,「能不能預判起漲族群」才有辦法回答。

## 2. 根因與設計方向

### 2.1 三個具體病灶(全部已對碼確認行號)

1. **C 級門檻是「任一條件通過」**(`_grade_new_gainer` :400 `if passed:`)。這等於沒有門檻——rule 7/8 幾乎恆真。
2. **C 級語意錯置**:C 級目前叫「C級個股事件」,語意是「少數個股帶動、非族群性」,但現在變成「至少一條件過」的垃圾桶,把大量無意義的族群日都掃進來。
3. **無「最低通過條件數」概念**:A 級要求 0 失敗、B 級要求 ≤4 失敗,但**都沒有要求「最少通過幾條」**。一個族群可以「4 條失敗、1 條通過、5 條無法評估」就拿 B 級。

### 2.2 設計方向(核心規則變更)

把分級從「失敗數導向」改為「**同時看通過數下限 + 失敗數上限 + 核心條件必過**」:

- **無訊號(GRADE_NO_SIGNAL)應是常態**:多數平凡族群日,通過的有效條件數不足,就應該是無訊號。
- **引入「核心條件」概念**:新起漲的本質是「族群性的、廣度擴張的、資金流入的起漲」。定義**核心條件集**(建議:rule 1 總分達標、rule 3 前 100 名家數增加、rule 4 成交額占比成長、rule 5 相對強度、rule 6 前 50 名家數)——這些是「真的有起漲」的證據;rule 7/8/9/10(不過熱、不過度集中、資料品質、映射覆蓋)是**否決型條件(veto)**,它們的作用是「不通過就擋掉」,而非「通過就加分」。
- **新分級邏輯(建議,Codex 可依資料實況微調但須在報告說明理由)**:
  - **A 級**:全部核心條件通過 + 全部否決條件通過 + 無失敗
  - **B 級**:核心條件通過 ≥ `min_core_passed_for_b`(建議 3)+ 否決條件無失敗 + 總失敗 ≤ `max_conditions_failed_for_b`
  - **C 級(重新定義為「個股事件」本義)**:僅在「有個股層強度證據(如 rule 6 前 50 名有量)但族群層廣度不足(核心條件通過 < B 級門檻)」時給,代表「這是少數個股的事,不是族群起漲」——**這才是 C 級原本該有的語意**
  - **無訊號**:以上皆不成立(這應成為多數族群日的結果)
- **無法評估的條件(unevaluable)不得算作通過**:目前 rule 7/8 常態「通過」是實質有評估到;但要確保「因缺資料而 unevaluable 的條件」不能填補核心條件通過數,否則會用缺資料反而更容易發訊號。

### 2.3 續漲訊號(GRADE_CONTINUED)

續漲目前是「0 失敗才算」(:495),看似嚴格,但 rule 5/6 恆為 unevaluable(:468-469),所以實際只要其餘幾條不失敗就成立。**同樣要求最低核心通過數**(建議:rule 1 連續達標 + rule 4 相對強度持續 這兩條為續漲核心,至少都要真的 passed 而非 unevaluable)。
